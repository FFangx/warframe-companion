# 产品行为合同

> 2026-09-05 设计收口；2026-09-06 D1c 市场部分已完成主管验收（148 项合成根测试、桌面打包、39/39 可见合成 Electron 流程与截图复核；真实 Warframe.Market 尚未实测），其余章节仍为设计。本文定义目标行为，现有源码状态见开发计划。游戏语义基线见 [OpenClaw 对齐清单](OPENCLAW_PARITY.md)，实施边界见 [交接工单](IMPLEMENTATION_HANDOFF.md)。

## 1. 产品与默认条件

Windows 桌面个人 Agent：总览给今天值得关注的情报与建议，左侧由用户添加、固定功能页面，右侧全局助手与工作区共享结果。完整继承 OpenClaw 功能范围；分期只决定先后，不削减功能。保留现有石墨灰/哑金工作台，不重做导航方案。

参数完整性由程序负责，不能把工具 Schema 变成玩家问卷。偏好服务保存带版本的交易范围和显示偏好，主进程每轮补全工具输入。首次缺少交易范围时提供一张简短选择卡，推荐 PC；选择后继续原查询，永久沿用并可在设置修改。已核实的旧配置可经一次可见导入沿用，不反复询问。跨平台 API 字段属于范围映射，不单独要求玩家理解或输入。

OpenClaw 快捷查询基线为 `platform=pc,crossplay=true`。PC 选项映射应保持该范围；不能因玩家说“只与 PC 玩家交易”偷偷改成 false。仅用户明确切换交易范围时更改；一次查询覆盖不自动永久改设置。无已保存配置的新安装只出现上述一次选择，不在每次问价重复设置。

条件优先级：本条明确条件/附加对象 → 同一实体适用的会话条件 → 已保存偏好 → OpenClaw 领域默认。等级属于物品条件，不是全局平台偏好：Prime 简称默认整套；明确部件查部件；可升级物品默认 0 级；“满级”由物品元数据求值；不适用等级的物品不显示等级表单。换物品重新验证等级，不能继承无效值。简称候选唯一直接查，多个合理对象才给选择。

## 2. 先回答，再考虑下一步

| 输入 | 预期行为 | 不应发生 |
|---|---|---|
| 母牛p多少钱 | 解析整套，沿用范围，给原市场模板内容和操作 | 追问平台、跨平台、整数等级 |
| 满级呢 | 继承刚查的可升级物品与平台，更新等级查新行情 | 重问物品或报旧价格 |
| 这个哪里刷 | 唯一上下文对象直接查；多个对象给名称选项 | 无依据选一个或要求重新写完整名字 |
| 太贵了 | 结合结果，适时提供“看看获取路线 / 到价提醒” | 自动创建订阅 |
| 今晚干什么 | 结合当前情报及可用个人信息先给建议和理由 | 无结果先问一整套偏好 |
| 只有半小时 | 更新时间限制并调整建议，保留原目标 | 从头介绍所有功能 |

选择、追问分两类：阻塞歧义结束本 run 并保存待答项；可选下一步随完整回答出现，不把已回答目标标为缺参。默认 0–2 个相关下一步，有帮助才出现。缺少耗时证据时不用概率冒充效率；缺个人数据照样提供公共建议，并指出能改善判断的那一项信息。

选择卡合同：主进程生成 `questionId/taskId/revision`，选项包含稳定 ID、可见标题和规范值；模型仅提出问题/候选，程序验证可选实体与字段。文本回答与点击同样有效。卡片留在聊天历史中，run 结束不消失；回答后标记所选项。被新问题替代的卡不可再执行，点击旧卡提示使用当前问题。可选动作包含 `actionId/kind/entityRef/resultVersion`，不用 Markdown 拼命令。翻页/复制本地执行；“满级”“哪里刷”等创建带结构化引用的新消息/run；订阅动作明确表达创建意图后才写入。

## 3. 结果和工作区

OpenClaw 原模板的信息、口径和层次是基线；原生卡可以折叠明细，但不能删掉关键内容。市场至少保留物品/等级、订单、统计口径、来源/时间、可用的图片与效果、税/杜卡德、整套散件比较及适用下一步。缺字段显示该部分不可用，不冒充整体失败。详见对齐清单。D1c 已按此补齐卡片与服务字段（统计含当前最低卖价相对 90 日中位的偏离并与历史口径分列；图片仅限 warframe.market 静态 https 资源；词条效果仅 MOD/赋能；套装散件单价×数量与合计比较，缺报价显式标“缺 N 件报价”且从不伪造合计）。

聊天摘要与详情引用同一个 `resultId/version`；翻页、筛选、展开不会重复调用模型。当前快照分页明确显示覆盖范围，不承诺是全部订单。刷新生成新版本，旧订单选择失效；用户显式复制只写剪贴板，原模板 `/w` 目标和语言规则由程序生成，不发送聊天。真实卖家与私聊文本不送模型、不进诊断。

主动附加对象在输入区可见可移除，发送时冻结引用。单纯切页不改变聊天指代、不自动开始任务。来源失效后保留历史展示，继续操作补查相关证据；历史订单重启后必须刷新，不能恢复为可复制的有效订单。

## 4. 聊天保存与恢复

消息、可持久化结果、明确条件、待答项默认保存在本机，切页/重启可继续查看和追问；可清空会话。历史时效事实标为历史，查询“现在”必须重新核验。重启将未完成 run 标为已中断，不自动续费、重放工具或重复执行本地动作。

采用主进程单写的版本化会话 JSON（每会话一个文件，独立索引，临时文件替换及上一份有效快照恢复）；不将历史写进 renderer localStorage。索引可由有效会话重建，损坏文件隔离并提示，不影响其他会话。保存失败明确提示“本次内容尚未保存”，保留内存内容并允许重试。未知版本只读保护，不覆盖。

落盘投影保留消息、实体/范围、公开结果摘要及来源、待答卡和已提交动作回执引用；不保存凭据、provider continuation、原始个人快照、订单卖家/私聊文本或图片原件。个人结果只保存所需的脱敏摘要，撤销授权后不再加载进模型。用户主动输入的聊天仅本机保存，不自动导出到日志。清空删除对应历史及结果文件/备份，撤销会话引用；不会删除独立订阅、周常或偏好，要在相应管理入口操作。

初始存储上限为单会话 20 MiB、总历史 256 MiB；到限不静默删聊天，提示归档/清理并允许新会话（总量到限先清理）。模型仅加载有界近期内容与相关结构化状态，不读全历史。活动证据初始上限 8 MiB，超限收束部分结果；这些是工程起点，验收测量后可调整，不能伪称已做容量测试。

## 5. 首页建议与提醒

总览优先展示最多 3 条当前建议，并可展开全部情报；公共世界状态产生候选，已授权目标/库存/完成记录补充约束。模型可比较和排序、解释取舍，领域服务提供数值和证据。显示理由、有效期、依据及未知项，提供查看/继续问/忽略；忽略绑定候选与周期，周期更新后可重新评估。无数据不填假建议。

后台刷新和订阅匹配用确定性服务，不周期性唤醒模型。打开页面展示现有结果；用户请求建议或刷新建议时才生成新的模型建议，依赖变化先标记待更新。用户订阅授权与个人摘要外发授权分开。

Windows 通知有设置开关，初始关闭；首次明确订阅可同时提供开启选项。不启用也保存订阅，在应用内提醒记录可见。只有明确订阅/到价监控可以发系统通知；未订阅机会仅首页展示。记录命中、入队、系统调用成功/失败，不能把系统调用成功称为用户已看见；点击通知打开对应结果，消失后仍可在提醒记录查看。

首次关闭 X 提供“留在后台 / 退出”，记住选择并可修改；留后台隐藏窗口，继续当前任务和显式订阅监测。明确退出取消 run、停止本机监测；不承诺退出后推送，不引入 Windows 服务。休眠恢复按当前状态补查，跳过已过期事件，以订阅/对象/阶段/周期去重。静音不删除订阅，重新启用不补发过时积压；新建个人掉落订阅先建基线，不能把已有库存当新掉落。

## 6. 模型和权限

以 DeepSeek Flash-vision 级别为主模型能力基准；短渐进计划、简洁工具合同、程序补默认值和精确计算，保留模型自主选工具和提出建议的职责。失败提供已有事实与明确缺口，不自动调用更强模型。真实模型是否可靠必须实测；OpenClaw CLI 实验不等于桌面 adapter 验收。

本地订阅/周常/愿望单明确请求可直接执行并给回执；推测意图不授权写入。游戏、市场交易、聊天、账号资产始终只读。桌面本地个人授权替代 QQ 专属身份流程，不能要求玩家为桌面功能输入 QQ 身份。既有 OpenClaw 继续独立运行；没有迁移工单就不读取其私有账本作为可写共享状态。
