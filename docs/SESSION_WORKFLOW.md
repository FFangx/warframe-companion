# 产品化 Session 工作约定

> 生效日期：2026-08-14

## 基本单位

每个 session 是一个可独立验收的小迭代，可以完成一步或紧密相关的几步。默认不以“写了多少代码”作为完成标准，而以可检查的产物和验证结果作为完成标准。

## Session 开始时

必须明确：

- 本次目标。
- 本次产物。
- 明确不做的内容。
- 验收方法。
- 是否会触及源码、运行时、个人状态或外部渠道。

若上个 session 留有未完成事项，先根据工作区记忆确认是否继续，不凭对话印象重复执行。

## Session 执行中

- 开始修改前检查相关仓库的 `git status -sb`，保留用户已有改动。
- 优先完成一个端到端垂直切片，避免同时铺开多个未验证模块。
- 代码、契约、测试和文档视为同一项工作的组成部分。
- 不因产品化工作扩大游戏或账号操作权限；所有现有只读边界继续有效。
- DeepSeek Harness 等快速变化的依赖先隔离验证，不直接成为稳定链路的强依赖。

## Session 结束条件

结束前必须：

1. 验证本次产物。
2. 说明改动文件、测试结果和已知限制。
3. 区分已实现、仅设计、尚未验证三种状态。
4. 更新 `OPENCLAW_WARFRAME_ASSISTANT_MEMORY.md`，记录日期、结论、路径、提交/推送和下一入口。
5. 指定下一 session 的建议目标，但不自动扩展本次范围。

若任务受阻，也要记录真实阻塞条件和已经确认的事实；不得把未完成目标写成完成。
