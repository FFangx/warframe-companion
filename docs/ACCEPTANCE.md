# 原型验证与发布验收

当前优先验证桌面原型能否完成用户流程。检查范围随改动选择，安装发布的要求在需要分发时使用。

## 原型切片

- 每次修改后从根运行 `npm test`，继续使用现有 CI。
- UI 修改实际启动或渲染，并走通本次流程；重点检查加载、无结果、失败与重试。复制、任务取消和切页等行为按实际变更验证。
- 工具/事实逻辑修改执行相关测试与确定性 eval；不因样式或文档修改扩大故障矩阵或运行付费模型评估。
- 构建配置修改执行 build，安装配置修改执行 `make`。文档修改检查链接、内容一致性与 `git diff --check`。
- 测试、截图与演示使用合成或脱敏数据；个人数据与游戏集成继续只读。

完成记录写清做了什么、实际验证了什么、还没试什么。UI 已可用不需要等安装包发布才能作为原型切片完成。

## 需要安装分发时

| 范围 | 届时需要的证据 |
|---|---|
| 源码与 CI | 固定提交的现有 build/test/eval 与仓库检查通过 |
| 制品 | 一致版本、源码提交、构建时间、安装制品与校验值 |
| 安装 | 安装、启动、卸载；有既有安装时验证升级与用户数据保留 |
| 使用 | 目标电脑上一条真实只读市场查询，来源/时间、失败提示与重试 |
| 发布说明 | 标注预发布/签名状态、已验证范围和已知限制 |

这些结果分别记录，不用源码测试替代安装或实机试用。Release 自动化在重复发布需要出现时再建设。
